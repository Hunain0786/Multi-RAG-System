# frontend — multi-rag chat UI

A Next.js 15+ (App Router) chat client for the multi-rag FastAPI backend. Renders the SSE stream from `POST /chat` and dispatches each `tool_use` / `tool_result` to a dedicated inline card (SQL tables, recharts, doc-citation cards).

## Stack

- Next.js (App Router, React 19, TypeScript strict)
- Tailwind CSS v4 + shadcn/ui (Radix primitives)
- recharts (bar / line / area / pie driven by the metric's `chart_hint`)
- react-markdown + rehype-highlight (assistant message rendering)
- Zustand (conversation state, persisted to `localStorage`)
- Sonner (toasts on the /docs page)

## Setup

```bash
cp .env.local.example .env.local   # set BACKEND_URL if backend is not on :8000
npm install
npm run dev                        # http://localhost:3000
```

`BACKEND_URL` is read **only** server-side (in `src/lib/env.ts`) and used by the route handlers under `src/app/api/*` to proxy through to FastAPI. The browser never sees it.

## How the SSE renders

The backend emits six event types (matching [backend/src/multirag/agent/loop.py](../backend/src/multirag/agent/loop.py)):

| Event          | Frontend action                                                        |
| -------------- | ---------------------------------------------------------------------- |
| `conversation` | Captured into Zustand state (persisted to `localStorage`) — sent back on the next request so history is durable |
| `text`         | Appended to the current assistant message (rendered as markdown)       |
| `tool_use`     | Pushes a `ToolCard` at the current position in the message flow        |
| `tool_result`  | Fills in the matching `ToolCard` with a per-tool renderer              |
| `stop`         | Marks the message complete, removes the streaming caret                |
| `error`        | Shows a red banner underneath the message                              |

`AssistantMessage.blocks` preserves the interleaving order so that a `search_docs` card that fired between two paragraphs stays between them.
